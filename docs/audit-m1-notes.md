## 2. Calibration decision: arrival anchor 0.6 → 1.0

At the declared 0.6 anchor, the arrival lane fired on **85–100% of
applicable files in every repo** (36/39, 216/237, 94/110, 37/37). Score
distributions: p25 ≈ 0.78–1.03, p50 ≥ 1.0 on all four repos. The
vibecoded segment simply has near-zero test co-change, so untested-share
saturates at 1 and a 0.6 anchor corroborates nothing — the ≥2-lane gate
degenerates to "size lane plus a rubber stamp."

Moved the anchor to **1.0 = every windowed touch arrived with no
reaching test**, the one crisp semantic point the saturated distribution
has. Post-change firing: 20/39, 179/237, 85/110, 37/37 — still high
(that is the segment's honest state), but firing now asserts a
zero-exception fact rather than a threshold nobody clears.

Known fragility, recorded: the arrival composite tops out ≈ 1.15–1.30
(untested 1.0 + capped bonuses), so a +1-step perturbation (×1.25)
disables the lane entirely. The anchor sits near the distribution
ceiling by construction. If M2 lanes give arrival more dynamic range
(cohesion, graph depth), revisit.

This is cross-repo refinement from **pre-ratchet firing data only**, per
§4's calibration-authority rule. No per-repo fitting occurred.

## 3. Anchor perturbation (±1 step = ±25%)

Ordering robustness is the claim that matters (rank-not-scores). Across
all four repos and all four perturbations (size ×0.75/×1.25, arrival
×0.75/×1.25):

- **Relative order of retained offenders: stable in 15 of 16 checks.**
  The one flip (hadoku_site, size ×0.75) reordered only newly-admitted
  members below the retained head of the list.
- Set membership changes as anchors move — expected, anchors gate entry.
  ×0.75 admits 3–6 extra files; ×1.25 drops the marginal half.
- arrival ×1.25 empties the offender list everywhere (the ceiling
  fragility above).

Verdict: ordering robustness holds at M1 scale.

The table is **degenerate and honestly so**: 99% of epoch files stayed
quiet over the window and every treatment decile has n ≤ 3. This is the
round-3 power problem measured in the field: single-repo backtests at
this scale cannot move any banded decision. Per §10.1 the corners stay
**recorded untested**. Lift claims need the M2 design-partner repos
and/or longer windows — see the derived n below.

## 5. §10.1 power simulation results (derived analytic constants)

Generated by `npx tsx scripts/audit-power-sim.ts` (seeded, reproducible).
Key derivations:

| base rate | falsification n (per group) | bands (null 2.5/97.5%) | power vs lift 2 |
|---|---|---|---|
| 0.1 | 800 | 0.74 – 1.35 | 100% |
| 0.2 | 200 | 0.67 – 1.45 | 98% |
| 0.3 | 200 | 0.73 – 1.33 | 100% |

Inspection sample size (state lanes, worst-case p = 0.5): **k = 50**
gives a ±14-point 95% band (the previously-declared k = 20 measures
±20 points — the "coin flip dressed as a decision rule" the design doc
predicted). Full quantile tables live in the script's output.

Consequence for the M1 backtest above: at vibecheck's ~1% corrective
base rate, no achievable n powers a lift test on this repo alone. The
falsification test becomes feasible only pooled across repos with
base rates ≥ 0.1 — an M2/M3 aggregation requirement, recorded here.

## 6. Observations for M2 (not acted on in M1)

- **Vendored code slips the exclusion pre-pass**: hadoku-conjure has a
  size score of 821 (≈ 330k adjusted lines) on a vendored
  `backend/custom_nodes/` file — path conventions don't catch
  ComfyUI-style vendoring. Consider suggesting `linguist-vendored`
  attributes in the report when a file exceeds an absurdity threshold.
- **The size lane fires on non-code text** (`docs/install.html`,
  `action.yml` at tier 1): scc counts their lines as code. The arrival
  lane restricts to code extensions; the size lane should probably do
  the same, or tier only scc's programming-language buckets.
- **Arrival saturation is a segment insight, not noise**: in repos with
  near-zero testing, test co-change cannot rank within the saturated
  mass; discrimination there comes from bulk arrival + snapshot churn
  only. M2's L4 static test-quality lane (which builds the real test
  graph) is what gives L3 its dynamic range back.
- **Ledger ordering bug found and fixed by a test flake**: same-
  millisecond events could fold in an order inverting creation order
  (floor reset before its own noise verdicts). ULIDs are now monotonic
  within a process; cross-process same-ms ties remain arbitrary-but-
  deterministic, per design.
